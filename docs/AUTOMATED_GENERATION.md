# 从图片自动生成并展示

在本机双击 `gso-viewer/start.bat`，选择 JPG/PNG，点击“用 TRELLIS.2 生成”。工作台自动上传图片和所需代码、提交 Slurm、查询状态、下载带纹理 GLB，并在新窗口展示。默认种子 42，一张 L20，最长两小时；每次点击创建独立任务，会使用学校计算额度。

## 首次使用条件

服务器沿用已安装的 `.venv-trellis2`、模型权重、`local/hpc4_modules.sh` 和 `slurm/load_hpc4_modules.sh`。本机需要 Python、OpenSSH，以及已成功配置的 SSH 密钥。新功能的代码由本机自动上传，无需手动更新服务器项目代码。

默认连接 `hkust-hpc4`，项目路径 `/home/rzhoubf/projects/cv-final-project`。需要改变时，在仓库根目录创建 `local/generation.json`：

```json
{
  "host": "hkust-hpc4",
  "project": "/home/rzhoubf/projects/cv-final-project"
}
```

连接使用无交互认证；若密钥有口令，先让本机 ssh-agent 加载密钥。SSH 首次主机验证需在终端完成一次，沿用现有连接即可。

## 自动执行过程

照片 → RMBG-2.0 抠图 → 居中缩放 → TRELLIS.2 形状和材质生成 → GLB 导出 → 下载展示。

图片最大 20 MiB，仅接受 JPG/PNG。抠图前将最长边缩至最多 2048 像素；本阶段保留照片细节，未添加降噪。复杂背景的质量优化属于下一阶段。

每个任务保存自己的执行代码与配置快照。服务器文件在项目的 `local/web-jobs/<任务编号>/`；本机在 `local/generation-jobs/<任务编号>/`，这些目录不提交 Git。服务器保留白模，默认只收取 `asset.glb`、`foreground.png` 和 `manifest.json`。本机不复制 GSO 数据集和模型权重。

## 状态与恢复

页面约每十秒查询一次，显示上传、排队、加载模型、抠图、生成导出、下载和完成。Slurm 设置的两小时是运行时间上限，排队时间单独计算。

关闭浏览器或本地工作台后，已提交的服务器任务继续运行；重新打开页面会查询已有作业。连接失败可点击“重新查询 / 下载”，此按钮只查询原作业，不再次提交。上传阶段关闭程序、或提交返回前断线，可能没有保存作业号；此时应先检查服务器队列中的 `web-任务编号前八位`，避免重复提交。

失败信息显示在任务列表；完整服务器日志在该任务目录的 `job.log`。GPU 超时、显存不足或抠图失败需要根据日志处理，再选择图片提交新任务。

完成任务提供“查看模型”按钮，首次查询到完成时也自动展示。保持工作台运行即可自动接收模型。当前完成记录按任务保存，历史 GSO 实验预设继续独立使用。

## 当前验证范围

本地模拟测试覆盖上传打包、Slurm 提交信息、结果收取、白模排除、失败日志及路径校验；viewer 原有测试一并通过。真实照片在远程 GPU 上的完整闭环需要一次实际生成确认，模拟测试不消耗 GPU 额度。
