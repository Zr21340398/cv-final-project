# 单图应用与批量实验

通过工作台导航打开“单图生成”或“批量导入”。两种模式都复用 `Pipeline` 和 `TrellisBackend`，使用同一个远端执行入口 `scripts/generate_remote.py`。本阶段保持既有 TRELLIS.2 模型与采样配置。

## 单图应用

启动 `gso-viewer/start.bat`，点击“单图生成”，选择 JPG/PNG，填写 SSH 别名、服务器项目绝对路径、作业时间上限，选择是否下载白模。单图默认种子 42、50 万面目标、2048 贴图。完成后模型会加入“模型对比”，也可以从生成任务中点击“查看模型”。

macOS/Linux 用户可在项目根目录运行 `python3 gso-viewer/server.py --open`。默认页面地址为 `http://127.0.0.1:8765/`；端口被占用时添加 `--port 8766`。

1. 点击 **预处理并预览**。服务器使用现有的固定版本抠图模型处理照片，然后返回原图、透明前景和模型实际使用的黑底 RGB 输入。点击预览图片可以放大检查。
2. 对照检查把手、边缘、细长部件是否完整，桌面、杂物、阴影和反光是否误留在前景。透明前景用棋盘格展示，第三张图包含模型预处理后的最终裁剪与黑底合成。
3. 有问题时可以 **重新选图**，也可以展开 **手动标记主体（可选）**。在原图上拖框圈出目标，添加保留点和排除点，再重新预处理。更换图片、连接设置、选框或标记都会清除旧确认。这里提供模型辅助分割，不提供逐像素画笔，也不会补出被手遮住的物体部分。
4. 图片正确时勾选确认，再点击 **确认前景并生成 3D**。未经确认不会提交 3D 推理；同一预览重复确认不会重复提交生成任务。刷新页面后可在任务列表点击 **检查前景** 恢复待确认任务。

预处理和 3D 生成是两个独立的 GPU 作业，均需学校 SSH 连接和现有 TRELLIS.2 环境，可能分别排队。预处理沿用现有模型加载流程，但只运行抠图和图像处理；完成后释放 GPU，不占用资源等待用户检查。确认后的生成固定引用预处理时的代码版本，校验原图、请求配置及预览文件摘要，直接使用已确认的前景和模型输入，不再次抠图或裁剪。

本功能接入 `gso-viewer` 单图工作台；批量实验与独立的旧版 Gradio/Hunyuan demo 保持原流程。预览只能帮助用户发现输入问题，不保证 3D 几何正确。

### 复杂背景的主体精修

默认仍使用 RMBG-2.0 自动抠图。手、包装或其他物品与主体相接时，显著前景检测可能把它们一起保留；仅保留最大连通区域无法解决这种情况。框选后改用固定版本 SAM 2.1 tiny，根据主体框和可选正、负点生成蒙版。使用单主体解码分支，再将未经阈值化的低分辨率 logits 作为蒙版先验精修两次；三次解码使用相同原图、选框和全部标记。每类最多 16 个点，坐标按转正后的原图记录。最终蒙版不满足保留/排除点时会报错，不能静默使用自动抠图替代。恢复旧预览后若要调整选框，需重新选择原图。

主体精修需在服务器独立准备 SAM 2 环境，并在 `local/hpc4_modules.sh` 中设置：

```bash
export ASSET3D_SAM2_CODE_DIR=/absolute/path/to/pinned/sam2
export ASSET3D_SAM2_CHECKPOINT=/absolute/path/to/sam2.1_hiera_tiny.pt
```

源码固定为 `facebookresearch/sam2` 的 `2b90b9f5ceec907a1c18123530e92e794ad901a4`，配置为 `configs/sam2.1/sam2.1_hiera_t.yaml`。使用 [Meta 官方固定权重](https://huggingface.co/facebook/sam2.1-hiera-tiny/resolve/de431c4043854a71d8101e17995dfe596bf101a5/sam2.1_hiera_tiny.pt)，文件大小为 156008466 字节，SHA256 为 `7402e0d864fa82708a20fbd15bc84245c2f26dff0eb43a4b5b93452deb34be69`。准备依赖时遵循[官方安装说明](https://github.com/facebookresearch/sam2/blob/2b90b9f5ceec907a1c18123530e92e794ad901a4/INSTALL.md)，可在独立环境复用已验证的 PyTorch/CUDA；本次验证使用 `hydra-core==1.3.2`、`omegaconf==2.3.0`、`antlr4-python3-runtime==4.9.3`、`iopath==0.1.10`、`portalocker==3.2.0`。当前调用关闭自动补洞和小区域清除，不依赖可选 SAM 2 CUDA 扩展；不会在线下载模型或修改旧环境。

选择记录进入 `request.json`；精修方法、固定版本、选择提示及候选分数进入 `segmentation.json`，其摘要一并纳入版本 2 的 `preview.json`。候选分数仅用于模型选取，不是人工质量评分。确认后的生成仍使用已核验的同一份 PNG，不再次分割。

真实手机照片对照中，原先单次多候选解码会残留相贴的小票，增加排除点还可能误删杯身；改用单主体分支与两次蒙版先验精修后，该样本的手、小票和杯身穿孔得到改善。更高计算精度或更大分割模型未解决原先的问题。该结果仅是一个样本的验证，不能保证所有照片同样有效，仍须逐次检查预览。有遮挡不等于抠图失败：3D 模型可以推测不可见区域，但这不保证真实还原，也不能替代对可见主体误删和杂物残留的检查。

本机和服务器的单图输入、配置、预处理及结果都位于项目的 `local/web-jobs/<任务编号>/`。本机 `local/generation-jobs/` 只存任务状态与远端作业编号，旧版任务数据仍保留。

新单图任务还保存 `preview.json`、`prepared/foreground.png`、`prepared/model_input.png`、`preview-job.sh`、服务器 `preview-job.log` 和 `preview-status.json`。正式结果额外保存已确认的 `model_input.png`，并在 manifest 的 identity 中记录其摘要；原始照片保留为输入记录。预处理失败时可重新选图，预处理作业查询或下载中断可重查原作业。提交返回前断线仍须先核实服务器队列，不自动重提。

## 批量实验

参考 `configs/web_batch.example.json` 修改配置，在“批量导入”中选择 JSON 文件和对应的多张图片。图片名必须与 `experiment.images` 完全一致；目前文件名仅支持英文、数字、点、下划线、短横线。页面提交前显示图片数、种子数、方案数和总生成次数。

示例包含 2 张图 × 2 个种子 × 2 个方案，共 8 次生成。每个方案支持：

- `name`：唯一方案名。
- `decimation_target`：减面目标，1000 至 1000000。
- `texture_size`：1024、2048 或 4096。

`seeds` 为不同的非负整数。实验名与方案名采用字母、数字、下划线、短横线。单批次最多 200 次生成；图片每张最多 20 MiB，网页合计最多 70 MiB。未知方案字段会报错，采样步数目前仍使用固定版本官方默认设置。

本机及服务器都创建同名 `experiments/<experiment.name>/`，已有目录会拒绝覆盖：

```text
experiments/trellis-photo-size-v1/
  request.json                  本次实验配置
  inputs/                       原始输入，只保存一次
  prepared/                     服务器抠图结果，多个方案复用
  job.sh、job.log、status.json   服务器作业和运行记录
  results/
    viewer-manifest.json
    failures.json
    faces1000k/image_000/seed-42/
      asset.glb
      shape_raw.glb             服务器保存；可选择下载
      input.png、foreground.png、manifest.json
```

每个方案下逐图、逐种子运行，同一作业内串行使用一张 L20。当前每个组合独立生成，没有实现一次生成、多档导出复用。普通单次推理失败会记录到 failures.json 并继续；环境初始化或抠图失败会中断整个作业。完成后自动下载成功结果和 viewer 清单，在生成任务中点击“查看实验预设”，再选择该实验、对象、种子和方案。失败组合保留失败记录。参考真值模型未在此上传格式中定义。

## 代码共享与版本固定

原实现每任务上传完整 src 会造成重复。本版把生成源码、配置和远端入口的内容计算为 SHA256，部署到服务器的 `local/code-releases/<摘要>/`。首次上传并完整解压后才写入可用标记；后续相同代码跳过上传，任务记录引用的代码摘要。代码更新形成新版本，正在运行的任务继续使用原版本。数据与结果目录都不保存源码副本。

共享的是项目执行代码；Python 环境 `.venv-trellis2`、模型权重 `models/`、学校模块配置及上游 TRELLIS.2 仍复用服务器已有安装。环境变更需单独部署。配置默认值可在 `local/generation.json` 中设置，批量模式以选中的 JSON 为准。学校账户 `mscaiehpc42026` 和分区 `gpu-l20` 目前固定，其他集群需调整。

## 进度、恢复与边界

本机通过 SSH/SCP 传输、提交 Slurm 并约每十秒查询一次状态；GPU 申请受学校规则约束。已提交作业在关闭页面后继续运行，重新打开工作台可继续查询和收取结果。查询/下载失败可重试原作业。提交返回前断线时，需要先查队列以避免重复提交。若本机服务在记录单图作业号前退出，重启后会显示“提交结果未知”，并提示核对预处理的 `preview-<任务编号前8位>` 或生成的 `web-<任务编号前8位>` 作业；系统不会自动重提。

默认只下载带纹理 GLB、输入/前景图、manifest 和失败记录；勾选后增加白模。下载的清单会移除未下载白模的路径。批量下载发生在整个作业正常结束后；超时作业的部分服务器结果保留，目前需人工收取，不会自动重提 GPU 作业。

旧的 GSO 历史批次及原批次执行命令保持原状。单图前景确认流程已于 2026-11-20 使用真实手机照片与学校 L20 完成 GPU 预处理、确认及 TRELLIS.2 生成测试；批量新模式的完整闭环仍需独立联调。本地测试覆盖配置、目录隔离、代码复用、任务提交参数、结果收取与 viewer。前景确认流程还覆盖预览与生成输入一致、内容改变拒绝、并发确认幂等、重启时提交状态未知及浏览器换图失效。

### 2026-11-20 真实手机照片验证与待办

本次使用手持纸杯照片：主体框与 6 个保留点、6 个排除点不变，改用单主体 logits 精修后，生产预览复现了诊断结果，手、相贴小票和背景被去除，可见杯口与杯身不再出现此前的误删孔洞。77 项相关 Python 回归测试通过，前端已有 15 项测试通过；独立 agent 完成代码和图像复核。该复核不等于用户人工评分，也不是多样本分割基准。

预处理作业 `2337355` 耗时 84 秒，后续单次 3D 作业 `2337381` 在香港时间 14:33:08–14:36:16 运行，均以 `COMPLETED/0:0` 结束。生成 manifest 记录原样复用确认前景，实际生成与导出耗时约 111 秒；服务器上的 5 项产物 SHA、原始网格几何和成品内嵌贴图检查通过；本地带纹理模型也通过 SHA 与几何/贴图核验，可在工作台加载。旋转观察发现：手、小票未带入 3D，但杯底仍不规则，背面文字与图案存在推测失真。因此本次证明了前景精修及确认输入的生成路径可用，不能据此声称遮挡区域已经准确还原。

后续优先验证细把手、透明反光物体、低对比边缘和多物体接触，并建立有人工标注的分割测试集；其次减少所需标记、将分割与完整 3D 模型加载分离、支持直接恢复旧选区。对明显遮挡应提示重拍或补充视角；如加入补全，须单独展示推测区域与原始观测，重新确认后再生成。当前尚未实现画笔修补、多视角重建或可靠的遮挡补全。

## Git 保存范围

`local/`（含单图任务、任务状态和共享代码缓存）、`experiments/` 下新增的实验批次、模型权重和数据集均由 `.gitignore` 排除。共享执行代码、通用配置示例和文档继续提交。此前已提交的历史实验配置及源码记录保留在 Git 中；本规则适用于后续新增批次，不改写已有历史。

### 服务器 GSO 面数实验

在原工作台选择「批量导入」，选择 `configs/gso_lod_six.json`，图片选择栏留空。配置的 `experiment.dataset` 为 `gso-v1` 时，`images` 中的路径相对于服务器项目的 `datasets/gso-v1/data/raw/gso/`。提交器在申请 GPU 前检查每张图片的可读性。已有的上传模式继续使用文件名列表并在页面选图。

此次使用 gso_01 的正面 2.jpg，以及 gso_03、18、23、27、29 的 0.jpg。插件 `shared_lod` 对每个样本和种子运行一次推理，基于同一原生形状和材质导出 100 万、50 万、20 万、10 万目标面的 GLB。种子为 42，贴图固定 2048。作业完成后在实验预设中比较各档，并运行 `python scripts/summarize_lod.py experiments/gso-lod-fridge-six-v1/results` 生成实际面数、字节数和体积降幅的 CSV。

### 单图默认导出与表面修复

单张图片默认使用一个种子和 50 万目标三角面，烘焙一次 2048 贴图。模型先生成原生形状与材质，再按目标面数导出。面数主要影响简化、烘焙及文件写入。端到端用时可在各任务的 manifest.json 中查看 attempts 下的 wall_seconds，并结合 native_shape_material、pbr_bake 和 export 分段分析。

单图自动启用 surface_repair。插件在写 GLB 前运行，局部修正与三角面严重反向的光照法线，并填补不透明贴图中四邻域材质一致的孤立全零采样点。修复计数和耗时在 manifest.json 的 export.surface_repair 中。几何重叠、模型推测出的图案或较大缺失区域需要另外诊断。

批量对照时可在 experiment 中设置 "export_plugin": "surface_repair"，并在 variants 中指定相同的 decimation_target 和 texture_size。对照批次省略 export_plugin，其他参数和种子保持一致。历史 shared_lod 配置继续用于多档面数实验。
